How it works

A coordinator takes OpenAI-compatible requests and runs them across community nodes, each holding a slice of the model’s layers. Every node’s owner stakes SOL. Every job is paid on Solana, a hidden sample is kept for a verifier, and proven fraud burns the stake.

Preview. Inference across slices, API keys, job records, audit evidence, stakes, payouts and slashes work today, on Solana devnet. The verifier that checks audited jobs isn’t built yet. See Status.

Roles

  • Clients call the OpenAI-compatible API with an API key. They never talk to nodes directly.
  • The coordinator (sinference/backend/) authenticates clients and nodes, hands out slices, runs every job step, keeps audit evidence, and sends payouts and slashes. Accounts, jobs and records live in Tiger Data.
  • Nodes run sinference up: a worker that loads a range of a model’s layers and runs them for each job. People join through Become a node.
  • The Solana program holds each owner’s stake, pays jobs into it from a vault, and burns it on proven fraud. The prototype runs on devnet.

Request lifecycle

  1. A client sends POST /chat/completions. The coordinator picks a copy of the model whose slices cover every layer, all ready.
  2. Each step goes through the coordinator, since nodes only make outgoing connections: token ids to the first slice, its hidden states to the next, and so on. The last slice samples the next token with the job’s seed.
  3. The client gets the reply as it’s generated, without waiting for verification or payment.
  4. The coordinator records the job: token counts, each node’s share, and hashes of the prompt, the output, and everything that crossed between slices.
  5. A payout transaction pays each node’s owner their share into their stake, with the job’s id and its record’s hash.

Verifying node output

A hash shows what a node sent, not that it ran the model. Nodes run jobs without checks in the moment. Their owners’ stakes make faking work a losing bet.

1. Stakes

Each account adds one Solana wallet for all its nodes, by its private key on the nodes page or in sinference up. A node only gets a slice while the account’s stake covers $20 of SOL for each of its nodes holding one; when a node joins short, the coordinator stakes the difference from the wallet, and a wallet that can’t cover it gets no work. Earnings are paid into the stake too. Both go back to the wallet automatically once the audits that could still catch them are past: earnings 10 minutes after their jobs, collateral once the account’s nodes have left. A slash burns whatever hasn’t gone back.

2. Hidden audits

For about 10% of jobs, the coordinator keeps everything that crossed each boundary between slices. It decides when the job starts, and every job looks the same to a node. Every job’s record already holds the hashes of those boundaries, so the kept evidence can’t be swapped later.

3. Verdicts

The verifier, the coordinator’s own compute, replays one slice of an audited job from its recorded inputs and compares the outputs. Blame is per slice, because a node that fakes its layers hands honest nodes after it bad inputs they process correctly. A fraudulent verdict burns the owner’s whole stake, bans their account and wallet, and drops their slices. Jobs nobody audits are final once paid.

Exact replays need the same GPU model, packages and attention kernel as the node; batch size is always 1. Mixed hardware needs a tolerance, which is still to be set.

Payouts on Solana

The program has two account types: Config (the coordinator’s key; its SOL is the payout vault) and Stake, one per wallet and account (a banned flag; its SOL is collateral plus earnings not yet released). Jobs aren’t accounts. They’re linked to the chain by their transactions.

InstructionSigned byEffect
stakeAccount’s wallet (its key, kept by the coordinator)Moves SOL from the wallet into the account’s stake, creating it the first time.
payCoordinatorMoves a job’s share from the vault into a stake, with the job’s id and its record’s hash.
releaseCoordinatorSends SOL from a stake back to its own wallet, and never anywhere else: earnings past their audits, or collateral once the nodes have left.
slashCoordinatorBurns the whole stake and bans it, with the audited job’s id and its evidence’s hash.

What nodes earn

A job is worth its tokens at its model’s price (see Models), converted to SOL at the current SOL/USD price. Its nodes split that by layers × speed in layers per second, measured on that job: nodes as fast per layer are paid by slice size, and equal slices by speed. Each job’s payout is one transaction into the owners’ stakes; it goes on to their wallets once the job’s audit window has passed.

The program runs on Solana devnet at 97VaN9bk…cULU. Devnet SOL is free from faucet.solana.com.

Trust model. The coordinator decides verdicts, and it keeps each account’s wallet key so it can stake for its nodes, which is fine for devnet wallets only. The chain makes every payout, release and slash public and limits what the program lets it do with stakes: pay from the vault, release only to a stake’s own wallet, and burn slashed SOL rather than keep it. Signed node outputs and independent verifiers would make verdicts checkable by others; neither is built.

Known limitations

  • The verifier isn’t built, so audited jobs keep their evidence but nothing checks it yet.
  • Every token crosses the coordinator once per slice, so nodes far from it are slow.
  • Text only: no tool calls, and POST /responses (Codex CLI) isn’t served yet.
  • The site handles one request at a time, so a long reply holds up others. Streamed replies arrive in one piece, and requests are capped at 64 KB and 120 seconds.
  • A payout costs more in transaction fees than it pays a node. That’s fine on devnet; real SOL would need payouts batched.
